# DART PARTY — 이동·착석 멀티플레이 프로토타입

Godot **4.6.3.stable.official.7d41c59c4**, GDScript, Forward Plus / D3D12, Jolt Physics.
실제 프로젝트는 이 폴더다. `project.godot`을 연다.
개발 규칙은 이 폴더의 `AGENTS.md` 한 파일에서 관리한다. 기본 화면은 1920×1080, 16:9이며 창 크기를 바꿔도 비율을 유지한다.

## F5: 혼자 시험

`app/main.tscn`의 Main 노드 Inspector에서 **Developer Mode** 기본값은 켜짐이다.
개발 빌드에서 F5를 누르면 UDP 7000 로컬 호스트를 만들고 플레이어 + 봇 1~3으로 바로 시작한다.
봇은 정지하며 자기 자리에서 과녁만 바라본다. 인터넷이나 외부 서버는 필요 없다.
7000 포트를 이미 쓰고 있다면 시작 화면에 방 생성 실패가 표시된다. 먼저 실행한 시험을 종료하거나 일반 모드로 다른 포트를 사용한다.

- WASD: 이동. 마우스: 시점/조준. Space: 점프. Ctrl 유지: 숙이기.
- E: 자기 색 자리 1m 이내에서 착석 / 앉아 있으면 일어서기. 숙이기와 별개다.
- 자기 차례에도 WASD/점프/숙이기와 마우스 조준을 자유롭게 사용한다. 시점과 발사 위치는 캐릭터를 따라가며, E 착석은 선택 사항이다.
- 왼쪽 버튼 유지: 최대 0.8초 충전(100%에서 유지). 놓기: 한 발 투척. 충전 중 오른쪽 버튼: 이번 충전 취소(다트는 손에 남고, 그 뒤 왼쪽을 놓아도 발사하지 않는다).
- 충전·조준 중에도 서 있으면 WASD로 움직일 수 있다(A/D 좌우). 앉아 있으면 E로 일어선 뒤 움직인다.
- 투척 가능할 때 오른쪽 아래에 다트가 보인다. 버튼을 놓으면 주황색 꼬리 날개가 달린 다트가 손 위치에서 과녁으로 날아간다. 하단 안내에 착석/차례/마우스 복귀/충전/발사 상태를 표시한다.
- 충전이 낮으면 속도가 작아져 더 아래로 떨어진다. 100%에서 중앙 조준은 불을 맞힌다.
- Esc: 마우스 해제/다시 잡기. 다른 창에서 돌아오면 게임 화면을 한 번 클릭해도 다시 잡는다. 복귀 클릭은 투척하지 않는다. 해제하면 하단의 대기실·시작 화면 버튼을 사용할 수 있다.
- F1: 봇 시야 표시/숨김. F2: 다음 봇.
- F3: 현재 미투척 턴을 시간 초과와 같은 경로로 0점 종료.
- F4: 선택한 봇 차례로 변경하고 20초 재시작. 경기 순서가 달라질 수 있다는 안내가 나온다.
- 비행·정산 중 F3/F4는 무시한다. F4는 현재 미투척 턴을 0점으로 정리한다.

오른쪽 위 보조 화면은 **같은 World3D**를 보는 320×180 SubViewport다. 맵·캐릭터를 복제하지 않는다.
봇 자신의 렌더 레이어만 카메라에서 제외하고, 사람 캐릭터는 메인 화면과 봇 화면에서 공유한다.
화면이 작으면 표시 크기를 줄이며, 마우스 입력을 받지 않는다. 봇이 없으면 숨긴다.

## 실제 4인 접속 시험

1. Main 노드의 **Developer Mode**를 끈다. 또는 각 실행에 `-- --normal`을 전달한다.
2. Godot `Debug > Customize Run Instances...`에서 Multiple Instances를 켜고 4개로 설정한 뒤 F5를 누른다.
3. 첫 창: 이름을 입력하고 포트 7000으로 **방 만들기**.
4. 나머지 3개 창: 서로 다른 이름, IP `127.0.0.1`, 포트 7000으로 **방 참가**.
5. 모두 **준비**를 켜고 방장이 **함께 시작**을 누른다.
6. 각 창에서 WASD/Space/Ctrl/마우스로 해당 캐릭터만 움직이는지 비교한다. 포커스 전환 시 Esc로 입력을 다시 잡는다.
7. 자기 차례에 서 있거나 앉은 상태로 왼쪽 버튼을 누르고 놓아 던진다. 모든 창의 차례·좌표·점수가 같은지 확인한다.
8. 한 사람은 자기 턴에 투척하지 않고 20초를 기다린다. 0점 후 다음 사람으로 넘어가는지 본다.
9. 마지막에 공동 순위와 방장의 재경기를 확인한다. 재경기 점수·다트·타이머가 초기화되어야 한다.
10. 추가 5번째 창은 가득 찬 방이라는 안내를 받아야 한다. 진행 중인 방은 경기 중이라는 이유로 신규 참가를 거부한다.

개발자 봇 교체 시험은 F5 → Esc → **대기실 / 봇 교체** → 다른 일반 모드 창에서 접속 순서로 한다.
접속한 사람마다 봇 한 명이 빠지고 총 4명을 유지한다. 새 참가자도 준비해야 한다.
**시작 화면으로**는 연결까지 종료하므로, 봇 교체 시험에는 대기실 버튼을 사용한다.

다른 LAN PC에서는 `127.0.0.1` 대신 방장의 내부 IP와 같은 UDP 포트를 사용한다.
계정, 서버 목록, NAT 우회, 호스트 이전은 제공하지 않는다.

## 경기 규칙

최고 누적 점수, 5라운드, 좌석 순서, 한 턴 3발, 턴 시작 즉시 20초다. 한 발 착탄 후 남은 발을 이어 던지며, 3발을 모두 던지거나 시간이 끝나면 다음 사람으로 넘어간다.
착석 여부와 관계없이 타이머가 시작되고 투척할 수 있다. 턴이 시작될 때 캐릭터를 자동 이동시키지 않는다.
비활성 턴에도 착석·일어서기와 이동이 가능하다. 투척 후 짧은 정산을 거쳐 다음 턴으로 간다.
봇도 기본 규칙에서 20초 후 0점이다. 동점자는 공동 순위다(1, 1, 3 방식).

**라운드 사이 테이블 집합**: 한 라운드가 끝나면(마지막 라운드 제외) 다음 라운드 전에 10초 동안 테이블 집합 단계가 있다. 이 안에 자기 색 자리에서 E로 앉아야 한다. 사람 전원이 앉으면 바로 다음 라운드를 시작한다. 시간 안에 못 앉은 사람은 자기 자리에 자동 착석되고, **다음 라운드 동안 이동 속도 50%(슬로우)** 페널티를 받는다(점수판·머리 위 이름에 `슬로우` 표시). 슬로우는 다음 집합이 시작될 때 풀린다. 봇은 늘 앉아 있어 페널티가 없다. 값은 `default_match.tres`의 `table_seconds`, `slow_speed_scale`.

표준 20섹터 배치, 싱글·더블·트리플·25/50 불을 적용한다.
반지름 경계는 불 또는 특수 링에 포함한다. 원주 반지름 1은 더블, 1 밖은 실패다.
섹터 각도 경계는 시계 방향 다음 섹터에 속한다. float32 좌표의 반올림 허용 오차는 정규화 1e-7이다.

방장이 신원·경기/턴 ID·요청 ID·차례·시간·유한 좌표·충전 범위를 검사한다.
방장만 환경 충돌과 과녁 평면 교차를 계산하고, 모든 화면은 확정된 시작점·종점·시간으로 비행을 재생한다.
캐릭터는 다트 충돌 마스크에서 제외한다. 바닥·벽·과녁 밖·2초 비행 제한은 0점이다.
과녁 앞 붉은 선은 이동 제한 구역이다. 사람끼리 밀지 않으며 캐릭터가 과녁 전체를 가리지 않도록 과녁을 높게 배치했다.

경기 중 이탈자는 제거하고 남은 사람으로 진행한다. 전체 참가자가 2명 미만이면 결과 화면을 띄운다.
방장이 나가면 모든 클라이언트는 안내를 보고 시작 화면으로 돌아간다.

규칙 설정은 `game/match/default_match.tres`, 충전·속도·중력·비행 제한은 `game/dart/default_dart.tres`에 있다.
이전 카드/효과 관련 파일은 이 프로토타입 실행 경로에서 사용하지 않는다.

## 자동 검증

이 폴더에서 Python 3과 Godot 4.6.3 실행 파일로 실행한다.

```powershell
$godot = 'C:\Users\아버지\Desktop\Godot_v4.6.3-stable_win64.exe\Godot_v4.6.3-stable_win64_console.exe'
python tests/run_multiplayer.py --godot $godot
python tests/run_first_idea.py --godot $godot
& $godot --headless --path . --script res://tests/test_rules.gd
& $godot --headless --path . --script res://tests/test_throwing.gd
& $godot --headless --path . --script res://tests/test_prototype.gd
& $godot --path . --script res://tests/render_first_idea.gd
& $godot --headless --path . --script res://tests/test_game_flow.gd
& $godot --headless --path . --script res://tests/test_art_showcase.gd
& $godot --headless --path . --script res://tests/test_game_look.gd
& $godot --path . --script res://tests/render_game_look.gd
```

개발자 시험 세 개(`test_prototype`, `render_first_idea`, `render_game_look`)는 기본 포트 7000을 쓰므로 순서대로 실행한다.
`render_game_look`은 약 20초 동안 전체 화면으로 실제 F5 장면을 찍어 저장소 최상위 `output/game_look/`에 둔다(디자인 피드백용).
네트워크 실행기는 별도의 빈 UDP 포트를 골라 실제 프로세스 2·3·4개를 띄운다.
봇 시야 검증은 실제 다중 프로세스 네트워크 검증을 대신하지 않는다.
실제 검증 결과와 남은 수동 재현은 `작업기록/HANDOFF.md`에 기록한다.
