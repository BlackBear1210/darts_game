# 멀티플레이 통신

현재 실행 방법은 [README](../README.md)의 실제 4인 접속 시험을 따른다.
ENet/UDP, IP 직접 접속, 방장 포함 2~4인이다. 기본 포트는 7000이다.
프로젝트는 Godot 4.6.3을 사용하고 `NetworkSession`을 `/root/Main/NetworkSession`에 유지한다.

## 로비와 실패

방 생성 → 이름·주소·포트로 참가 → 모두 준비 → 호스트 시작 → 로딩 완료 장벽 → PLAYING 순서다.
봇은 호스트가 관리하는 내부 참가자로 실제 피어 수나 로딩 장벽에 포함하지 않는다.
대기실이 4명일 때 봇이 있으면 실제 등록자에게 그 빈자리를 준다. 사람 4명이면 가득 참을 표시한다.
진행 중 참가에는 경기 중이라는 거부 RPC를 보내고 참가자가 연결을 닫는다.
구체적인 거부 사유 전달을 위해 전송 계층은 임시 등록 전 연결을 허용하지만 실제 방 정원은 RoomState의 4명이다.
등록·로딩 확인은 실제 RPC 발신자와 현재 상태를 검증한다. 오래된 로딩 확인은 무시한다.
접속 대기는 8초, 화면 로딩은 10초 뒤 안내와 함께 복구한다.

## 경기 메시지

화면별 노드에 직접 RPC하지 않고 지속 NetworkSession에서 실제 발신자 ID를 붙여 로컬 signal로 전달한다.
Game은 이동·착석을, MatchController는 투척·턴·점수를 검사한다.
명령과 경기/비행 사건은 reliable 채널, 이동 입력/스냅샷은 별도 unreliable_ordered 채널 1/2다.
경기 ID와 증가 시퀀스를 검사해서 다른 경기의 패킷·역순 패킷을 폐기한다.
움직임은 서버 물리에서만 계산하고 클라이언트는 서버 위치를 20Hz로 받는다.
투척은 방장이 환경 충돌/과녁 적중을 확정하며 캐릭터는 다트 충돌에 영향을 주지 않는다.

## 이탈과 재경기

경기 중 이탈자는 로스터와 캐릭터에서 제거한다. 남은 참가자가 2명 이상이면 진행한다.
활성 투척자가 이탈하면 미완료 비행을 취소하고 다음 차례로 진행한다. 2명 미만이면 종료한다.
호스트가 나가면 클라이언트는 안내와 함께 시작 화면으로 돌아간다. 호스트 이전은 없다.
호스트만 결과 화면에서 재경기 또는 전체 대기실 복귀를 요청할 수 있다.
재경기는 기존 연결을 유지하면서 점수·다트·턴 시계를 초기화한다.

## 실제 검증과 남은 검증

`tests/run_multiplayer.py`, `tests/run_first_idea.py`는 봇을 제외한 실제 ENet 프로세스를 2·3·4개 실행한다.
같은 PC의 loopback 검증이며 서로 다른 LAN PC, 패킷 손실/지연, 외부 인터넷 접속을 검증한 것은 아니다.
LAN 수동 시험은 다른 PC에서 같은 프로젝트를 일반 모드로 실행하고 방장 내부 IP/UDP 포트를 입력한다.
Windows 방화벽과 실제 LAN 경로는 해당 환경에서 확인해야 한다. NAT 우회·계정·서버 목록·매칭은 범위 밖이다.
