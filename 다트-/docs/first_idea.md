# 첫 번째 아이디어: 원형 테이블 다트

## 현재 플레이

기존 로비에서 2~4명이 준비한 뒤 시작하면 원형 테이블에 배치된다.
중앙 과녁이 투척자의 방향으로 회전하고 수직으로 올라온다. 플레이어와 카메라는 자기 좌석을 유지한다.
관전자는 자신의 자리에서 다른 플레이어를 보고, 오른쪽의 공개 과녁 미리보기로 배치와 직전 착탄점을 확인한다.

최고점 개인전 4라운드, 턴당 2발이다. 점수가 같으면 공동 순위다.
캐릭터·손·테이블·의자는 기본 도형을 사용한 임시 외형이며 자유 이동은 없다.

## 투척 조작

1. 자기 차례에 과녁이 멈추면 화면의 조준점을 원하는 위치로 옮긴다.
2. 마우스 왼쪽 버튼을 유지한다. 하단 게이지가 왕복한다.
3. 게이지 중앙의 노란 선에서 버튼을 놓으면 정확하게 던진다.

별도 무작위 빗나감은 없고, 타이밍 오차에 따라 착탄점이 조금 이동한다.
비행 중 추가 투척은 받지 않는다. 과녁 이동·정산·카드 단계에는 투척할 수 없다.
턴당 12초이며 마지막으로 수락한 다트는 비행을 마친 뒤 채점한다. 시간 초과의 미사용 발은 0점이다.
과녁 구역 밖은 0점이고, 빗나간 다트는 테이블 쪽으로 떨어진다.

## 카드

첫 라운드는 카드 없이 진행한다. 이후 라운드 사이에 전원 공통 15초 카드 단계가 열린다.
현재 카드 종류가 3종이므로 후보는 각 종류 1장씩 순서를 섞어서 제공한다. 후보와 사용 예약은 본인만 받는다.
보유 카드와 적용 효과는 전원에게 공개한다.

| 카드 | 대상 | 효과 |
| --- | --- | --- |
| +10 | 자신 | 다음 턴에 맞힌 각 다트에 +10 |
| ×2 | 자신 | 다음 턴에 맞힌 각 다트의 기본 점수 ×2 |
| 점수 섞기 | 다른 참가자 | 다음 턴의 1~20 숫자 구역 배치 섞기 |

후보 1장 선택 → 보유 카드 클릭 → 대상 확인 → **사용 예약** 순서로 사용한다.
후보 선택은 한 번만 확정하고 사용 예약은 마감 전 수정할 수 있다. **이번에는 보관**으로 예약을 취소할 수 있다.
카드 효과는 단계가 끝날 때 적용된다. 카드 후보를 고르지 않으면 첫 후보를 보관하고 사용은 생략한다.
최대 3장을 보관하며 초과하면 가장 오래된 카드가 교체된다.
카드 단계의 오른쪽 선택 메뉴로 자기 과녁과 상대 과녁을 확대해서 볼 수 있다.

효과는 대상의 다음 투척 1턴 동안 유지하고 턴 종료 후 사라진다.
점수 섞기는 링과 불을 유지한다. 방장이 숫자 배치를 생성해 모두에게 전달한다.
점수는 과녁 판정 → 배율 → 가산 순서로 계산하며 빗나감은 카드가 있어도 0점이다.
같은 단계의 여러 카드 사용은 좌석 순서로 적용한다.

## 얼굴 방해

다른 사람의 조준 단계에 **얼굴 장난**을 누른다.
짧은 예고 뒤 투척자 화면 가장자리에서 얼굴과 효과음이 나온다. 캐릭터도 짧게 반응한다.
상대마다 턴당 1회, 전체 최대 2회이고 동시에 중첩하지 않는다.
얼굴은 한쪽 폭 10% 안쪽에 표현해 중앙 과녁과 숫자를 가리지 않는다.
다트 궤적과 점수는 직접 바꾸지 않는다.

## 연결과 경기 진행

- 방장이 참가자 목록, 차례, 시간, 카드, 착탄, 점수를 확정한다.
- 클라이언트는 입력을 요청으로 보내고 확정 결과로 연출한다.
- 경기·턴·요청 ID와 발신자·입력 범위를 검증한다. 늦은 요청과 중복 투척은 채점하지 않는다.
- 중요한 경기 상태와 다트·방해 사건은 reliable RPC로 전달한다.
- 카드 후보는 해당 참가자에게만 보내며 공개 경기 스냅샷에 포함하지 않는다.
- 접속 중이나 경기 중 이탈하면 기존 정책대로 로비 복귀/방 종료를 처리한다.
- 방장은 **로비로 돌아가기**로 결과 화면에서 다시 시작할 수 있다.

실제 버튼 입력을 증명하는 별도의 부정행위 방지나 외부 인터넷 릴레이는 이번 구현 범위가 아니다.

## 수정할 위치

경기 수치는 `game/match/default_match.tres`, 카드 규칙은 `game/cards/card_controller.gd`에 있다.
순수 점수 계산은 `game/board/board_scorer.gd`, 링·숫자 데이터는 `board_layout.gd`에 있다.
공간과 장치는 `game/table/`, 캐릭터는 `game/player/`, 화면은 `ui/`에서 수정한다.
연결 노드는 `Main/NetworkSession`, 경기 RPC 노드는 `Main/Game/MatchController`로 유지한다.

## 검증

`test_rules.gd`는 불·링·각도 경계, 빗나감, 배율/가산, 카드 소유권·후보 분리와 스냅샷을 검사한다.
`run_first_idea.py`는 실제 2·3·4인 프로세스로 4라운드를 완주하고 전원의 결과를 비교한다.
잘못된 차례·이전 턴·중복 요청·범위를 벗어난 입력·잘못된 카드 대상·방해 횟수를 검사한다.
뷰포트에 마우스 이벤트를 전달해 조준·버튼 유지·놓기에서 실제 투척 요청까지 연결되는 경로를 확인한다.
입력이 없어도 턴·카드 제한 시간으로 경기가 끝나는지 검사한다.
`render_first_idea.gd`는 실제 Forward Plus/D3D12 렌더러로 2·3·4인의 모든 좌석과 카드·결과·방해·관전 화면을 저장한다.

실행 방법은 [README](../README.md)를 참고한다.
