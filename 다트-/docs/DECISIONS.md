# 설계 결정

## 2026-10-15: 자유 이동 투척과 턴당 3발

- 사용자 요청에 따라 공용 투척 카메라/원점을 제거했다. 시점은 캐릭터를 따르고 방장은 실제 발신자 캐릭터의 눈 위치에서 비행을 계산한다.
- 턴당 3발, 기존 20초 제한을 유지한다. 착탄 후 발수와 시간이 남으면 같은 턴에서 다음 발을 던진다. 비행 중 중복 요청은 기존대로 거부한다.

## 2026-10-15: 투척에서 착석 조건 제거

- 사용자 확인: 자신의 차례이면 앉아 있든 서 있든 투척할 수 있다.
- Game의 입력·카메라, HUD 게이지, 방장의 요청 검증에서 착석 의존성을 제거했다. E 착석은 선택적인 이동/자세 기능으로 유지한다.
- 이전 문서의 착석 후 투척 조건은 이 결정으로 대체한다. 기존 차례·발수·시간·권한·점수 판정은 유지한다.

## 2026-10-15: 이동·착석 DART PARTY와 개발자 모드

- 사용자의 새 요구를 현재 규칙으로 적용한다. 아래의 기존 왕복 타이밍·고정 비행 시간 결정은 현재 실행에서 대체되었다.
- Main/NetworkSession, 표준 과녁 채점, Resource 설정, DartView의 해석적 포물선 재생을 재사용했다.
- 사람의 이동은 방장 CharacterBody3D에서 계산한다. 상대 캐릭터는 밀지 않고 다트 판정을 막지 않는다.
- 고정된 벽 과녁과 공용 투척 시점으로 변경했다. 착석은 자기 자리에서 요청하며 차례 시작에 캐릭터를 이동시키지 않는다.
- 규칙은 5라운드·1발·20초, 충전은 포화하는 속도 입력이며 카드 단계/효과/얼굴 방해를 활성화하지 않는다.
- 방장이 중력·환경 레이·과녁 평면 교차로 비행 종점을 먼저 확정하고, 각 화면은 같은 시작점·종점·시간을 재생한다.
- RPC를 지속 NetworkSession에 모았다. 실제 다중 프로세스 시험에서 화면 제거 후 이동 패킷이 삭제된 Game 경로를 찾는 오류를 발견해 수신 수명을 수정했다. 점수 규칙은 계속 MatchController가 소유한다.
- 봇은 실제 피어와 별도로 표시한 방 내부 참가자다. 음수 참가자 식별자를 RPC 대상으로 사용하지 않는다.
- 봇 보조 화면은 같은 World3D와 캐릭터별 시각 레이어를 사용한다. 복제 맵이나 별도 OS 창은 없다.
- F3/F4는 기존 시간 초과/턴 시작 경로만 사용하고, 비행/정산 중에는 무시한다.
- 과녁 경계 float32 오차는 정규화 1e-7로 명시했다. 불/특수 링에 포함하고 각도는 시계 방향 다음 섹터로 정한다.


## 2026-10-15: 투척 설정과 비행 책임

- 결정: `DartConfig`가 투척 설정과 공통 운동 계산을 소유하고, `DartThrowController`는 입력·요청, `DartView`는 비행, `TrajectoryPreview`는 궤적 표시를 맡는다. UI는 다트를 직접 제어하지 않는다.
- 이유: 사용자가 지정한 HANDOFF의 책임 분리를 실제 코드에 반영하고, 예상 궤적과 비행이 같은 설정을 사용하게 한다.
- 시간·판정: 기존 방장의 착탄·점수 판정과 `MatchConfig.flight_seconds`를 유지한다. 초기 속도는 확정된 착탄점과 도착 시각으로 계산한다.
- 영향: Tween 비행이 등가속도 운동으로 바뀐다. 독립적인 물리 충돌 판정과 자유 투척 세기 규칙은 도입하지 않는다. 기존 마우스 유지 시간의 왕복 타이밍을 사용한다.

## 2026-10-16: 전용 서버와 선수 방장 분리

- 결정: 같은 프로젝트의 Game/MatchController를 별도 headless export 프로세스에서 실행한다. 서버 ID 1은 선수 목록에 넣지 않고, `RoomState.host_peer_id`로 선수 방장을 별도 기록한다.
- 이유: 기존 이동·투척·채점 권한을 재사용하면서 실제 참가자 2~4명을 수용하고 에디터 없이 실행하기 위해서다. 새로운 전역 서비스나 중복 게임 구현은 만들지 않는다.
- 영향: 첫 접속자가 방장이고 이탈하면 다음 사람에게 관리 권한을 넘긴다. 서버는 계속 경기를 소유한다. 전원 이탈하면 빈 로비로 재사용한다. 방장 요청도 서버가 실제 RPC 발신자로 검증한다. 일반 호스트/개발자 봇 방식은 유지한다.
- 검증 빌드: export template은 CLI의 임의 script/Scene 경로 override를 지원하지 않으므로 `verification` feature에만 테스트 시작 Scene을 지정한다. 배포 서버·클라이언트에는 테스트 파일을 제외한다.
- 이탈 처리: 다중 이탈 시험에서 ENet의 닫힌 채널 전송 오류가 재현됐다. 상태 갱신을 이탈 poll 뒤로 모으고, 서버만 경유하는 구조에 필요 없는 참가자 간 자동 알림/중계(`server_relay`)를 끈다.

## 2026-10-16: 기본 실행의 로그 초기화 충돌 회피

- 재현: 기본 서버 실행은 로그 파일 열기 실패 후 0xC0000005로 종료됐고, 쓰기 가능한 --log-file 지정 시 정상 시작했다. 4.6.3 엔진은 FileAccess::open 실패 후 null 검사 없이 detach_from_objectdb를 호출한다.
- 결정: project.godot의 자동 파일 로그(기본/PC)를 끄고 콘솔 출력을 유지한다. 명시적 파일 저장은 쓰기 가능한 --log-file 경로를 사용한다. 게임/네트워크 로직은 변경하지 않는다.
- 검증: 기본 서버·콘솔·D3D12 플레이어 시작 및 명시적 파일 로그 저장 회귀를 추가했다. 전용 서버 시험도 --log-file 없이 시작하도록 변경해 기본 실행을 검증한다.

## 2026-10-16: 로컬 개발 계정과 영구 경기 결과

- 사용자 확인: 아직 Steam App ID가 없으므로 로컬 개발 로그인부터 연결한다.
- 결정: Python 표준 라이브러리의 loopback API + SQLite로 최소 계정/프로필/전적 흐름을 구현한다. 외부 공개용 서비스나 Steam 인증으로 간주하지 않는다. Godot에서는 Main 소유 BackendConnection/HTTPRequest로 연결한다.
- 권한: 클라이언트는 사용자 토큰만 전달하고, 경기 서버가 API에 토큰을 확인한다. API에서 확인된 계정 ID/이름을 사용한다. 결과 제출은 별도 서버 키로 제한한다.
- 저장: 5라운드·3발 정상 완주/사람 경기만 집계한다. 최고점 공동 승리를 허용한다. 현재 프로토타입의 정책이며 미구현 목표 점수 근접 모드를 대신 확정한 것이 아니다.
- 복구: 결과 ID별 대기 JSON을 먼저 기록하고, 저장 확인 후 삭제한다. API는 같은 결과 ID를 한 번만 반영한다. Godot JSON 재로드의 정수/실수 차이를 정규화해 같은 결과의 재시도를 구분하지 않는다.
- 배포: DB/키/백엔드는 PCK와 Git에서 제외한다. Steam 티켓 인증·운영 DB/HTTPS·여러 방 할당은 후속 작업이다.
