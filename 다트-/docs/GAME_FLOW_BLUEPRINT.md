# 게임 진행 청사진

요청 근거: 저장소 상위의 `게임진행흐름도.png`. 전체 순서와 분기를 확인하는 **실행 가능한 로컬 시연**이다. 세부 규칙을 확정하거나 기존 멀티플레이 경기를 교체하는 작업은 아니다.

## 실행

Godot에서 `game/flow_preview/flow_preview.tscn`을 열고 **F6 (현재 씬 실행)** 을 누른다. 별도 서버·로그인이 필요 없다. F5는 기존 3D 멀티플레이 프로토타입을 실행한다.

저장소 최상위의 `실행_흐름도시연.cmd`를 더블클릭해도 된다.

한 사람이 버튼으로 모든 가상 참가자를 조작한다. 인원 2~4명, 시연 라운드 수, 목표 점수, 합동 라운드 번호(0=없음)를 설정하고 다음 단계를 누른다. 투척 직전에는 점수 입력과 발사/페이크 버튼, 다른 참가자의 방해 버튼을 사용할 수 있다. 참가자 줄에 점수·손패(종류별 장수)·취기가 보인다. 결과 화면 또는 중간에 `처음부터 다시 보기`로 초기화한다.

## 구현된 진행

```text
시작 → 방 생성/입장 → 모드·설정 → 테이블 집합 → 카드 획득 (전원 7장) → 순서 결정
  → 라운드 시작
    ↳ 합동 라운드 번호와 같으면: 바텐더와 다 같이 한잔 (전원 취기 +1)
  → 현재 플레이어 (3발)
    → 이동·위치 선택 → 카드 사용(연산/다트/과녁/물리 중 가진 종류)/미사용 → 투척 준비 → 조준·충전
      ↳ 다른 참가자 방해: 한 발에 한 사람당 1장
      ↳ 페이크·취소: 조준 유지 (발수 차감 없음)
      ↳ 발사: 점수 반영 → 3발 미완료면 이동 단계로
    → 3발 완료: 다음 사람 / 전원 완료면 전원 테이블 복귀
  → 종료 조건 확인
    ↳ 계속: 카드 보충 — 7장까지만 (안 쓴 사람은 0장) → 다음 라운드
    ↳ 종료: 목표 점수와 차이 비교 → 순위 → 게임 종료
```

> 실제 경기(F5) 반영 (2026-10-26): "전원 테이블 복귀"는 MatchController `TABLE` 단계로 구현했다. 라운드 사이 10초 안에 자기 자리에 앉아야 하며, 못 앉으면 자동 착석 + 다음 라운드 이동 속도 50%. 자세한 내용은 `docs/ARCHITECTURE.md` 권한과 통신 절.

이동·자동 복귀·조준·충전·카드 효과는 단계 표시로 표현한다. 투척은 0~60의 입력 점수로 대체한다. 물리 판정이나 실제 캐릭터 이동을 수행하지 않는다. 카드 사용과 방해는 손패에서 1장을 빼고 기록만 남긴다(효과 수치 없음).

## 미정 규칙과 시연용 대체값

| 항목 | 시연 동작 | 팀원이 결정할 부분 |
| --- | --- | --- |
| 모드 | 목표 점수 근접 비교 1종 | 실제 모드 목록과 모드별 규칙 |
| 카드 지급 | **확정**: 매 라운드 7장까지 채움, 안 쓰면 0장. 종류별 확률은 같음(시연값) | 종류별 지급 확률 |
| 순서 | P1부터 고정 순서 | 추첨·선택 등 결정 방식 |
| 카드 종류 | **확정**: 연산·다트·과녁·물리 4종 | 종류별 세부 카드(+15, ×2, 바람 …)와 효과 수치 |
| 카드 사용 | 매 발 선택, 가진 종류 중 1장 소비 | 대상·적용/취소·소멸 시점 |
| 방해 | 조준 중 다른 참가자가 1장, 한 발에 한 사람당 1회, 손패 맨 앞 카드 | 중첩 여부·종류 선택 UI·방해 시간 |
| 합동 라운드 | 설정한 1개 라운드에서 전원 취기 +1 | 주기·내용(바텐더 이벤트)·취기 효과 |
| 경기 종료 | 기본 2라운드, 시작 전에 변경 가능 | 실제 종료 조건 |
| 순위 | 목표와 절댓값 차이 오름차순, 동점 공동 순위 | 초과 점수·동점 규칙 |

흐름도 이미지의 2장→1장 교환은 10.23 회의(새로고침·임의 버리기 없음)와 7장 보충 규칙에 따라 뺐다. 3발과 위에서 확정이라고 적은 것 외의 수치는 시연값이다. 페이크는 발사 전 조준만 취소하며 이미 사용한 카드의 반환 여부는 구현하지 않았다. 이 씬의 결과는 백엔드 전적에 저장하지 않는다.

## 코드와 후속 연결 위치

| 파일 | 책임 |
| --- | --- |
| `game/flow_preview/game_flow.gd` | UI에 독립적인 단계·반복·손패/취기/점수, `actions()`와 `act()` |
| `game/cards/card_hand_rules.gd` | 손패 7장 채우기·카드 4종 순수 규칙 (실제 경기에서도 재사용할 부분) |
| `game/flow_preview/flow_preview.gd` | 단계 설명·설정 입력·버튼·최근 진행 표시 |
| `game/flow_preview/flow_preview.tscn` | F6 실행 진입점 |
| `tests/test_game_flow.gd` | 손패 규칙, 2·3·4인 완주와 카드/방해/합동 라운드 분기, 순위, 씬 실행 및 선택적 렌더 검증 |

실제 경기로 옮길 때는 `game/match/match_controller.gd`가 서버에서 단계를 확정하고 `match_state.gd`로 공유한다. 이 로컬 시연 모델을 클라이언트의 공유 상태로 사용하지 않는다. 실제 요청은 지속 `network/network_session.gd`에서 실제 발신자 권한을 검증하는 계약을 유지한다.

- 방·설정: 기존 `lobby/`와 NetworkSession의 로딩 장벽에 연결.
- 집합·복귀·자유 이동: 기존 `game/game.gd`, `game/player/`, `game/table/`에 연결.
- 조준·충전·발사·채점: 기존 `game/throwing/`, `game/dart/`, `game/board/`를 재사용.
- 카드 지급·사용·방해: 지급은 `CardHandRules`를 서버(MatchController)에서 호출한다. 세부 카드·효과는 `game/cards/`에 추가한다. 과거 고정 좌석 카드 구현을 그대로 활성화하지 않는다.
- 합동 라운드·취기: 연출은 `art/`(바 앞 공간), 화면 효과는 `ui/`, 발생 라운드는 `match/` 설정으로 나눌 수 있다.
- 종료·순위: 현재 누적 최고점 규칙과 다른 목표 근접 규칙이다. 백엔드의 승수/완주 저장 정책도 함께 검토해야 한다.

범용 매니저·네트워크 메시지·미사용 인터페이스는 추가하지 않았다. 팀원이 세부 구현을 시작할 때 위 항목을 나누어 맡을 수 있다.

## 검증 명령

Godot 루트에서 `$godot`에 Godot 4.6.3 콘솔 실행 파일을 지정한다.

```powershell
& $godot --headless --path . --script res://tests/test_game_flow.gd
& $godot --path . --script res://tests/test_game_flow.gd -- --render
```

렌더 이미지는 `.godot/flow_preview_render/`에 저장한다. 실제 멀티플레이 검증은 기존 테스트의 영역이며 이 시연의 가상 참가자로 대체하지 않는다.
