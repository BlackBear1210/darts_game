# 첫 번째 아이디어 구현 계획

상태: 사용자의 “진행해” 승인으로 구현한 첫 프로토타입의 기준 계획.
실제 조작과 구현 규칙은 [first_idea.md](first_idea.md)를 참고한다.

## 목표와 근거

2~4명이 원형 테이블에 앉아, 중앙 장치에서 올라오는 과녁에 차례대로 다트를 던지는 멀티플레이 프로토타입을 만든다.
테이블은 카드 선택 공간과 투척 공간을 겸한다. 플레이어는 자리를 유지하며 서로의 상태와 반응을 볼 수 있다.

참고 문서: 상위 폴더 `다트게임기획_첫번째_두번째_세번째아이디어.pdf`.
- 2~3쪽: 첫 번째 아이디어의 공간, 장치, 카메라, 진행 방식.
- 11~14쪽: 개인 상태 과녁, 카드 반복, 화면 가독성, 방해, 캐릭터 방향.
- 15~16쪽: 비교와 확인 기준. 문서의 2안 우선 추천 대신 사용자가 선택한 1안을 구현한다.

문서의 시간·횟수·밸런스는 제안이다. 아래의 수치와 세부 효과 규칙도 사용자 검토를 위한 제안이다.

## 구현 목표 범위

포함:
- 기존 방 생성·참가·준비·전원 로딩 확인 재사용.
- 2~4인에 맞춘 원형 테이블 좌석, 간단한 캐릭터와 1인칭 카메라.
- 중앙 과녁의 내려감, 회전, 상승과 입력 잠금.
- 개인별 과녁 배치·효과 데이터, 머리 위 상태 표시와 중앙 과녁 연결.
- 차례별 조준·던지기·착탄·득점·최고점 경기 종료.
- 첫 투척 라운드 이후 전원 동시 카드 선택과 사용.
- 대표 카드 3종, 화면 가장자리의 짧은 표정 방해 1종.
- 라운드·차례·발수·시간·점수·공개 효과 표시, 결과와 로비 복귀.

후속 범위:
- 0점 만들기·목표점 근접 모드, 2대2, 원본의 나머지 카드와 변형 과녁.
- 자유 이동, 다른 공간 구성, 코인·베팅·인형뽑기·꾸미기, 음성 채팅.
- 외부 인터넷 릴레이·매칭·호스트 이전.

처음에는 기본 도형과 간단한 얼굴로 실제 구도와 반복을 확인한다.
최종 캐릭터 모델과 펍의 장식 제작은 기본 반복이 작동한 뒤 진행한다.

## 공간과 카메라

- 테이블 중심은 공용 장치이고 그 주변에 참가자를 균등하게 배치한다. 경기 중 좌석은 고정한다.
- 과녁은 평소 테이블 아래로 내려가 있다가, 내 차례에 내 방향으로 회전하고 수직으로 올라온다.
- 장치의 회전은 내려간 상태에서 수행한다. 과녁 아래쪽은 테이블 위로 올라오고 비행 경로는 비워 둔다.
- 실제로 맞는 과녁은 하나다. 현재 투척자의 개인 과녁 데이터를 중앙 장치에 표시한다.
- 머리 위 작은 과녁은 공개 상태 표시다. 중앙 과녁과 같은 데이터로 그려 점수·효과가 어긋나지 않게 한다.
- 각 클라이언트는 자기 좌석의 눈높이 카메라를 사용한다. 조준 중 카메라는 정면에 고정한다.
- 관전자도 자기 좌석에 남는다. 활성 과녁을 뒤에서 보는 자리에는 공개 과녁 미리보기와 착탄 결과를 UI로 제공한다.
- 투척자의 오른쪽 아래에는 다트/손 표현, 왼쪽 아래에는 카드와 효과 요약을 둔다.
- 중앙 과녁, 점수 숫자, 조준점이 캐릭터·카드·손·HUD에 가려지지 않도록 구성한다.
- 테이블 크기, 눈높이, 과녁 크기와 거리는 2·3·4인 구도를 확인하면서 조정한다. 정식 다트 규격을 강제하지 않는다.

## 한 판의 흐름

```text
로비 → 전원 준비·로딩 → 첫 투척 라운드
                          ↓
              과녁 준비 → 조준·투척 → 정산 → 다음 사람
                          ↓ 전원 투척 완료
                     라운드 종료 확인
                       ↙         ↘
              카드 선택·사용       최종 순위
                    ↓                ↓
              다음 투척 라운드      로비 복귀
```

- 첫 라운드는 카드 없이 모두 한 턴씩 던진다.
- 이후 라운드 사이에 전원 동시에 카드를 선택하고, 공개 정보를 보면서 카드를 사용할 수 있다.
- 투척 순서는 경기 시작 시 좌석 순서로 확정하고 한 판 동안 유지한다.
- 투척자 변경마다 장치를 내리고, 다음 투척자의 배치와 방향으로 준비한다.
- 과녁 이동·카드 단계·정산 중에는 투척을 받지 않는다.
- 장치 전환은 방장이 확정한 단계와 전환 정보로 각 화면이 재생한다. 고정 좌석과 장치 위치를 매 프레임 전송하지 않는다.
- 방장은 장치 전환이 완료된 뒤 조준 단계와 제한 시간을 시작한다. 각 화면도 자체 전환이 끝나기 전에는 입력을 잠근다.
- 마지막 라운드 후 총점을 비교한다. 동점은 공동 순위로 표시한다.

## 승인받을 초기 규칙

| 항목 | 제안 | 성격 |
| --- | --- | --- |
| 인원 | 2~4인 개인전 | 이번 프로토타입 범위. 팀전은 후속 |
| 모드 | 최고점 경쟁 1종 | 세 모드 중 하나를 먼저 구현 |
| 경기 길이 | 4라운드, 1인 1턴 2발 | 조절 가능한 임시 설정 |
| 투척 입력 | 마우스 조준 → 왼쪽 버튼 유지 → 타이밍에 맞춰 놓기 | 초기 조작 제안 |
| 투척 제한 | 조준이 열린 뒤 턴당 12초 | 이동·정산 시간은 제외, 미사용 발은 0점 |
| 카드 단계 | 전원 공통 15초 | 개인별 순차 대기 없음 |
| 카드 후보 | 각자 비공개 후보 3장 중 1장 선택 | 후보 생성과 선택은 방장이 관리 |
| 보유·사용 | 최대 3장 보유, 카드 단계당 최대 1장 사용 | 미사용 카드는 보관 |
| 선택 시간 초과 | 후보 첫 장 보관, 카드 사용 생략 | 초과 보유는 오래된 카드 교체 |
| 카드 효과 기간 | 대상의 다음 투척 1턴 | 해당 턴 종료 후 해제 |
| 동점 | 공동 순위 | 추가 연장전 없음 |
| 연결 해제 | 기존 정책 유지: 남은 인원 로비 복귀, 방장 이탈 시 방 종료 | 기존 검증된 처리 재사용 |

이 값들은 확정된 원본 규칙이 아니다. 승인 후 하나의 경기 설정 Resource로 관리한다.
시간 제한이 경기를 자동으로 끝내도록 하고, 연출 완료 여부와 네트워크 로딩은 별도로 처리한다.

## 다트와 점수

- 처음에는 일반 원형 과녁의 숫자 구역·더블·트리플·불을 사용한다. 구역 밖은 0점이다.
- 표시와 판정은 같은 과녁 배치 데이터를 사용한다.
- 조준점과 타이밍에서 착탄점을 계산한다. 초기 버전에는 별도의 무작위 빗나감은 넣지 않는다.
- 클라이언트는 정규화된 조준점과 타이밍 입력을 요청으로 보낸다. 점수를 직접 보내지 않는다.
- 방장은 현재 투척자·단계·남은 발수·입력 범위·경기/턴/요청 ID를 확인한다.
- 방장은 입력으로 착탄점과 점수를 확정하고 다트 시작점·착탄점·비행 시간을 전원에게 전달한다.
- 모든 화면이 같은 결과로 비행을 표현한다. 다트 끝은 오른손 위치에서 중앙 과녁까지 자연스럽게 이어진다.
- 한 번에 한 발만 처리한다. 수락된 요청은 한 번만 득점하며 이전 턴 요청과 중복 요청은 무시한다.
- 타이밍 입력 검증은 가능한 범위와 차례를 보장한다. 조작된 클라이언트의 실제 버튼 입력을 증명하는 별도 부정행위 방지는 이번 범위가 아니다.

## 대표 카드 3종 제안

| 카드 | 대상 | 다음 투척 1턴의 효과 |
| --- | --- | --- |
| +10 | 자신 | 유효하게 맞힌 각 다트의 기본 득점에 10 추가 |
| ×2 | 자신 | 유효하게 맞힌 각 다트의 기본 득점을 2배 |
| 점수 섞기 | 상대 1명 | 숫자 1~20의 구역 배치를 섞음. 링 배율과 불은 유지 |

- 빗나감은 가산·배율 카드가 있어도 0점이다.
- 보유 카드와 적용 효과는 공개하고, 선택 전 후보는 해당 플레이어에게만 전달한다.
- 카드 사용은 대상 선택 → 효과 미리보기 → 확인으로 진행한다.
- 사용할 카드는 단계 중 잠정 선택하고 단계 종료 시 방장이 확정한다. 마감 전에는 선택을 수정할 수 있다.
- 여러 효과는 좌석 순으로 확정한다. 점수 계산은 과녁 배치 적용 → 기본 판정 → 배율 → 가산 순서를 제안한다.
- 점수 섞기의 난수와 실제 배치는 방장이 생성해 전달한다. 클라이언트마다 따로 섞지 않는다.
- 개인 상태 과녁은 현재 적용 효과를 표시하고, 카드 사용 대상의 다음 턴에 중앙 과녁이 같은 상태를 사용한다.
- 효과 종류는 3종에 필요한 작은 분기로 구현한다. 전체 카드 목록용 범용 효과 프레임워크는 미리 만들지 않는다.

## 방해와 캐릭터

- 임시 캐릭터는 큰 머리·단순한 눈과 입, 좌석별 색상으로 구분한다.
- 첫 방해는 고개 삐죽 내밀기/눈 깜박이기 한 종류로 구현한다.
- 조준 중에만 사용 가능하며 상대마다 턴당 1회, 전체 최대 2회를 초기 제한으로 제안한다.
- 한 번에 한 행동만 재생하고, 예고 0.3초·행동 1초·행동 간 간격 0.5초를 문서의 임시값으로 검토한다.
- 투척자 화면의 좌우 가장자리에서만 표현한다. 중앙 80%는 보호하고 얼굴은 한쪽 폭 10%, 높이 25% 이내를 목표로 한다.
- 방장이 사용 권한과 횟수를 확인해 사건을 전송한다. 방해는 다트 경로나 점수를 직접 변경하지 않는다.
- 효과음은 자유 음성 채팅과 분리하며, 초기 얼굴 방해를 확인한 뒤 짧은 지정 효과음 하나를 연결한다.

## 코드 책임과 추가 파일

아래는 승인한 역할 분리 기준이다. 현재 해당 기능을 사용하는 파일을 구현했다.

| 위치 | 역할 |
| --- | --- |
| `game/table/table.tscn`, `table.gd` | 테이블·좌석·중앙 장치 배치, 상승·하강·회전 표현 |
| `game/player/player.tscn`, `player.gd` | 캐릭터, 상태 과녁, 표정 표현 |
| `game/board/board_layout.gd`, `board_scorer.gd`, `board.gd` | 배치 데이터, 순수 판정, 화면 표현 |
| `game/throwing/throw_controller.gd` | 로컬 조준·타이밍·투척 요청 |
| `game/dart/dart.gd` | 확정된 결과의 비행·착탄 표현 |
| `game/match/match_config.gd`, `match_state.gd`, `match_controller.gd` | 설정, 경기 상태, 방장 진행·요청 검증·동기화 |
| `game/cards/card_definition.gd`, `card_controller.gd` | 대표 카드 데이터, 후보·보유·선택·적용 |
| 기존 `app/main.gd`, `game/game.gd`, `ui/game_hud.gd` | 요소 연결과 화면 표시 확장 |

기존 `NetworkSession`은 연결·방·입장 처리를 유지한다. 투척·카드·점수 로직을 그 파일에 몰아넣지 않는다.
게임 로딩 완료 후 동일한 `Main/Game/MatchController` 경로에서 경기 RPC를 받도록 연결한다.
`RoomState.Phase`는 방의 입장 상태로 유지하고, 세부 카드·준비·조준·정산 단계는 `MatchState`에서 관리한다.
현재 임시 플레이어 생성 코드는 새 Player 씬으로 교체하고 중복 코드를 제거한다.
데이터·규칙은 UI나 3D 씬에 의존하지 않는다. 연출 완료 사건과 경기 상태는 상위 소유 노드가 연결한다.
범용 Manager, 미사용 인터페이스, 미래 모드의 빈 구현은 만들지 않는다.

## 구현 순서와 단계별 확인

1. **공간·카메라**: 원형 테이블과 2~4인 좌석, 중앙 장치, 개인 상태 과녁. 각 좌석에서 과녁 정면과 비행 경로 확인.
2. **기본 멀티 경기**: 차례·조준·투척·점수·4라운드 종료. 모든 화면에서 같은 다트와 점수가 표시되는지 확인.
3. **카드 반복**: 첫 라운드 이후 선택·보유·사용, 대표 카드 3종과 개인 배치. 공개/비공개 정보와 효과 해제 확인.
4. **방해·리액션**: 얼굴 방해와 짧은 반응, 화면 가장자리와 사용 제한 확인.
5. **통합 검증**: 2·3·4인 완주, 결과·로비 복귀·재시작, 접속 해제, 요청 중복과 늦은 입력 확인.

각 단계는 실행 가능한 상태에서 다음 단계로 진행한다. 최종 완료 범위는 1~5 전체다.

## 완료 기준

- 2·3·4인 모두 자기 좌석에서 같은 테이블과 참가자를 본다.
- 활성 과녁은 현재 투척자 방향을 향하며, 이동이 끝나기 전에는 누구도 던질 수 없다.
- 자기 차례인 사람만 제한된 발수를 던지고, 손·다트·테이블의 위치가 자연스럽게 연결된다.
- 전원의 과녁 배치, 착탄, 점수, 라운드, 적용 효과가 일치한다.
- 첫 라운드에는 카드가 없고, 이후에는 공통 카드 단계와 순차 투척을 반복한다.
- 비공개 후보는 상대 화면에 전달되지 않는다. 사용한 카드는 소비되고 효과는 정해진 턴 후 사라진다.
- 얼굴 방해가 중앙 과녁과 숫자를 가리지 않고, 서버에서 횟수를 제한한다.
- 연결 해제와 경기 종료 시 화면·상태를 정리하고 로비에서 다시 시작할 수 있다.
- 기존 다중 프로세스 테스트를 통과하고, 점수 경계·카드 효과·차례 검증을 추가한다.
- 실제 렌더링 화면으로 2·3·4인 각 좌석의 가독성과 다트 시작점·착탄 위치를 확인한다.

## 승인 기록

사용자가 위 계획을 검토한 뒤 “진행해”로 구현을 승인했다.
최고점 개인전, 4라운드·2발, 타이밍 조작, 카드 3종, 제한된 얼굴 방해를 첫 프로토타입에 적용했다.
이 수치들은 첫 구현의 설정이며 이후 플레이 검토에 따라 조정할 수 있다.
