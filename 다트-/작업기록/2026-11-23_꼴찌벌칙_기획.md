# 2026-11-23 · 꼴찌 벌칙 — 현재 상태 확인과 기획안

> 이 문서는 **기획안**이다. 아직 구현하지 않았고 확정된 규칙도 아니다.

## 1. 확인 결과 — 없어진 게 아니라, 애초에 F5 에 들어간 적이 없다

| | 벌칙 원판 |
|---|---|
| **F6 카드 라운드 시연** (`game/card_round/card_round.tscn`) | **있다. 지금도 돈다.** |
| **F5 실제 경기** (`game/game.tscn` · `MatchController`) | **한 번도 없었다.** |

- 파일은 `game/card_round/fx/punishment_wheel.gd` (87줄) 하나뿐이고, 부르는 곳은 `card_round.gd _punishment()` 와 `flow/dart_actions.gd punish_throw()` 뿐이다.
- `git log -S "punishment" -- game/match/ game/game.gd ui/game_hud.gd` → **결과 없음.** F5 쪽 코드에 벌칙이 들어왔다 지워진 이력이 없다.
- F5 는 `MatchState.Phase.FINISHED` 가 되면 `ui/game_hud.gd` 가 "경기 종료" + 순위 글 + 재경기/로비 버튼만 띄운다.
- `docs/GAME_FLOW_BLUEPRINT.md` 의 단계 표에도 벌칙 항목이 없다.

F6 를 자동 진행으로 끝까지 돌려 실제로 확인했다(`intro → cards → card_turn → darts → ending → **punish** → results`, 꼴찌 1번 자리가 원판에 묶임).

### 지금 F6 벌칙이 하는 일

- 꼴찌(`RoundRules.loser()` = 순위 맨 뒤)를 지름 1.9m 서커스 원판에 팔다리 벌린 자세(`Wheel_Spread`)로 묶는다.
- 원판은 1.5rad/s 로 돌고 2~4초마다 **방향과 빠르기를 바꾼다**.
- 나머지가 순서대로 **2발씩** 던진다. 원판에 꽂히면 판과 같이 돈다.
- 몸(머리 원 + 몸통 상자, 팔은 제외)에 맞으면 **스턴 별 + "아야!" 음성 + 토스트**. 그게 전부다.
- 끝나면 골드 정산(`award_gold`) → 결과 화면.

## 2. 그대로 F5 에 옮기면 안 되는 이유

1. **네트워크가 없다.** F6 는 한 프로세스에서 혼자 돈다. F5 는 방장 권한 구조라 원판 각도·다트 판정·맞음 여부를 **방장이 확정해서 뿌려야** 한다. `MatchState.Phase` 에 단계를 더하고(기존 숫자가 밀리지 않게 **맨 뒤에** — `match_state.gd` 주석), 원판 각도를 상태에 실어야 한다.
2. **꼴찌가 아무것도 안 한다.** 4인 기준 약 17초 동안 가만히 맞기만 한다. 진 사람에게 **벌과 지루함을 같이** 주는 셈이다 — 파티 게임에서 제일 나쁜 조합이다.
3. **던지는 쪽도 걸린 게 없다.** 맞혀도 별과 토스트뿐, 골드·기록에 안 남는다. 그래서 대충 던지게 된다.
4. **인원에 따라 길이가 들쭉날쭉하다.** 2인이면 1명 × 2발 = 4초, 4인이면 6발.

---

## 3. 기획안 A (추천) — 원판을 **양방향 게임**으로

이미 만들어 둔 원판을 살리면서 가장 큰 결함(꼴찌가 구경만 함)을 고친다.

### 1단계 · 기본 이식 (네트워크 포함)

- `MatchState.Phase` 맨 뒤에 `PUNISH` 추가. `FINISHED` 앞이 아니라 **`FINISHED` 직전 단계**로 끼운다.
- 방장이 꼴찌를 확정 → 원판을 다트 홀 레인(투척선과 과녁 사이)에 세우고 꼴찌 캐릭터를 붙인다.
- **원판 각도는 방장이 상태에 실어 보낸다**(각도 + 각속도, 클라이언트는 보간). 클라가 제 시계로 돌리면 서로 다른 그림을 보고 판정이 어긋난다.
- 다트 판정은 기존 `solve_throw` 뒤에 원판 평면 교차 + `PunishmentWheel.hits_body()` 를 더한다 — **둘 다 이미 있다.**
- **던질 발수 = 인원에 상관없이 총 6발 내외**로 맞춘다: `max(2, ceil(6 / (인원 − 1)))` → 2인 6발 / 3인 3발 / 4인 2발. 길이가 늘 15~20초로 고정된다.

### 2단계 · 꼴찌에게 조종권 ← **이 기획의 핵심**

- 꼴찌는 **A/D(또는 마우스 좌우)로 원판 회전을 가속·감속**한다. 빨리 돌수록 맞기 어렵다.
- 대신 **어지러움 게이지**가 찬다. 가득 차면 원판이 **1.5초 동안 딱 멈춘다**(= 공짜 과녁).
- 꼴찌 화면은 돌아가는 1인칭이다. 카메라를 같이 굴린다 — `game/match/card_screen_effects.gd` 가 이미 `ONESHOT_ROLL` 로 화면을 굴리고 있어 그대로 쓸 수 있다.
- → 꼴찌가 **"언제 힘을 아낄지" 고르는 판단 게임**이 된다. 맞아도 제 선택이라 덜 억울하고, 피하면 짜릿하다.

### 3단계 · 걸린 것 만들기

- 몸에 맞음 = **던진 사람 +골드, 꼴찌 −골드**. `RoundRules.award_gold()` 뒤에 더한다.
- **전부 피하면 꼴찌에게 "버텼다" 보너스.** 꼴찌 벌칙이 역전의 기회가 된다 — 이게 있어야 꼴찌도 벌칙을 기다린다.
- 킬로그(`MatchController.feed_entry`)에 "○○ 이 △△ 를 맞혔다" 를 남긴다.

### 방 설정 스위치

`lobby/room_settings.gd` 에 `@export var punishment: bool = true` 를 더한다. 처음 하는 사람이나 불편한 사람이 끌 수 있어야 한다. 기존 `cards_enabled`·`props_enabled` 와 같은 자리에 둔다.

## 4. 다른 안

### B · 펍 탈출 (가장 역동적, 새 기하 필요)

꼴찌를 다트 홀에 풀어놓고 **20초 안에 반대쪽 문까지 달리게** 한다. 나머지는 투척선에서 던진다. 맞으면 그 자리에서 1.5초 스턴. 문에 닿으면 탈출 성공.

- 이미 있는 것: 7.2m 레인, 캐릭터 이동, `game/dart/body_hit.gd` 캡슐 판정, 스턴.
- 새로 필요한 것: 도착 지점(문) 기하와 판정, 꼴찌 전용 카메라.
- **장점**: 꼴찌가 진짜로 도망친다. 보는 재미가 가장 크다.
- **걱정**: 좁은 레인에 3명이 쏘면 너무 쉽게 잡힐 수 있다. 엄폐물(술통 4개가 이미 있다)을 살려야 성립한다.

### C · 벌주 / 소원 (가장 싸다)

꼴찌가 감정표현 하나를 강제로 하거나, 1위가 목록에서 벌칙 한 줄을 고른다. `emote_wheel` 재사용이라 코드가 거의 공짜지만 **게임성은 없다.** A 를 만들기 전에 임시로 넣을 수 있는 가장 싼 벌칙이다.

### D · 복수전

꼴찌가 원판 대신 과녁 앞에 서고, 먼저 1발 던져 "보호 칸" 을 고른 뒤 나머지가 던진다. 재미있을 수 있지만 규칙이 복잡해지고 설명이 길어진다. 지금 카드 59종으로도 이미 복잡하다 — **권하지 않는다.**

---

## 5. 추천

**A 의 1 → 2단계.** 이유:

- 이미 만들어 둔 원판·`hits_body`·스턴 별·`Wheel_Spread` 자세를 전부 살린다. B 처럼 새 기하를 만들지 않아도 된다.
- 가장 큰 결함(꼴찌가 구경만 함)을 2단계가 바로 고친다.
- 1단계만으로도 "F6 에 있던 게 F5 에 왔다" 가 되고, 2단계는 그 위에 얹는 작은 추가다. 쪼개서 커밋할 수 있다.

**가장 큰 일은 벌칙 자체가 아니라 네트워크다.** 원판 각도·다트 판정·맞음 여부를 방장이 확정하고 뿌리는 부분이 이 작업의 실제 분량이다.

## 6. 정해야 할 것 (팀)

- 벌칙을 기본으로 켤지 끌지.
- 골드 ±얼마. "버텼다" 보너스 얼마.
- 어지러움 게이지가 차는 속도와 멈추는 1.5초 (2단계).
- 원판을 레인 어디에 세울지 — F6 값 `Vector3(0, 1.25, -4.6)` 은 과녁이 3.6m 앞이던 시절 값이다. 지금 레인은 7.2m 라 다시 잡아야 한다.
- 2인 경기에서 6발이 맞는지.
