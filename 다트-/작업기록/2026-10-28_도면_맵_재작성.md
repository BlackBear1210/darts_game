## 치수 환산

도면에 숫자가 없어 **스툴 지름 0.6m**를 자로 삼았다(1m ≈ 133px).

| 도면 | 환산 |
| --- | --- |
| 위쪽 다트 홀 | x −4.0 ~ +4.0, z −5.0 ~ 0.0 (8.0 × 5.0m) |
| 아래쪽 라운지 | x −5.6 ~ +8.1, z 0.0 ~ +5.0 (13.7 × 5.0m) |
| 과녁 벽 → 투척선 | 2.33m → `THROW_LINE_Z = -2.7` (과녁 면까지 2.0m) |
| 플레이어 테이블 | 중심 (0, 0, 2.95), 2.15 × 1.55m |
| 자리 4개 | (−1.5, 2.95) · (0, 4.2) · (1.5, 2.95) · (0, 1.75) |
| 바 카운터 | x −3.9 ~ −2.95, z 0 ~ 4.95 |
| NPC 자리 | x 3.3 ~ 4.95, z 2.2 ~ 3.7 + 스툴 2개 |
| 당구대 | x 6.3 ~ 7.8, z 1.85 ~ 4.4 |
| 럼주통 | 큰 통 4(반지름 0.4) + 작은 통 4(0.2) |

도면은 좌우 단차 위치가 0.7m 다른데(왼쪽이 더 위) 손그림 오차로 보고 **z=0 한 줄로 정리**했다. 그래야 방이 사각형 두 개의 합집합이 되어 벽·바닥·클램프가 전부 단순해진다.

## 투척 구역 규칙 (같은 날 추가)

방만 바꿔서는 부족했다. 물어볼 때 "자리에서 과녁이 안 보인다"고 적은 것이 **틀렸고**, 다트 홀 입구가 8m라 자리에서도 직선으로 보이고 맞는다(앉은 플레이어가 불을 맞히는 것을 `run_first_idea.py` 가 확인). 그래서 규칙으로 막았다.

- `TableView.in_throw_zone(point)`: 다트 홀 안인지. 과녁 앞은 투명 벽이 막으므로 "다트 홀 안 = 투척선 뒤"다.
- `MatchController.in_throw_zone`: GameView 가 주입하는 Callable(`check_seated` 와 같은 방식 — 컨트롤러는 씬을 모른다). 사람 요청(`_accept_throw`)과 봇(`bot_throw`) 둘 다 확인한다. 주입이 없으면(씬 없는 시험) 위치를 보지 않는다.
- 로컬 화면도 같은 조건으로 `throw_input.enabled` 를 잠근다 — 라운지에서는 손에 다트가 안 보이고 충전도 안 된다.
- HUD 안내: "다트 홀로 이동하세요 · 투척선 뒤에서만 던질 수 있습니다".
- `tests/run_first_idea.py` 투척 시나리오를 다시 썼다: 자기 차례가 되면 일어나 **테이블을 피해 옆길로 돌아 투척선까지 실제로 걸어가** 던지고, 다음 사람 차례 동안 자리로 돌아가 앉는다.
  시험의 집합 시간은 `fast_match` 가 1초로 줄여 두기 때문에 **라운드의 마지막 투척자만 집합에 늦는다** — 그 사람만 자동 착석 + 슬로우를 받는 것을 검증한다(전에는 "앉기로 한 사람 / 아닌 사람" 기준이었다).
- `tests/test_prototype.gd`: 라운지에서 던지면 거부되는지 확인하고(조준 잠금 + 경기 상태 불변), 그 뒤 다트 홀로 들어가 기존 투척·마감 검사를 잇는다. 투척 거리가 2m로 짧아져 비행이 0.3초라 고정 대기(1.2초)로는 정산까지 끝나 버려서, 착탄을 기다리는 방식으로 바꿨다.

### 짧아진 비행이 시험에 준 영향

투척 거리 3.6m → 2.0m 로 비행이 약 1초 → **0.3초**가 됐다. `run_first_idea.py` 의 "같은 턴에 두 번 요청해도 1발만"은
명령 파일 왕복(~0.2초)이 비행보다 길어져 **두 번째 요청이 비행이 끝난 뒤 도착해 정상 투척이 되어** 버린다(실제로 3인에서 실패했다).
비행 중 잠금은 같은 프로세스에서 확정적으로 검사할 수 있으므로 `test_prototype.gd` 쪽에 맡기고,
네트워크 시험에서는 한 발이 정확히 50점씩만 더해지는지(누적 합)로 추가 투척이 없음을 본다.

## 넓히기와 레인 옆 개방 (같은 날, 사용자 피드백)

사용자가 직접 돌려 보고 세 가지를 말했다: ① 발사 기능이 사라진 것 같다 ② 맵이 너무 좁다 ③ 과녁·투척 자리 옆이 줄로 막혀 있는데 옆으로 가서 방해·구경하게 뚫어 달라.

- **①은 기능 고장이 아니라 바로 위에서 넣은 규칙이었다.** F5 시작 자리가 라운지라 조준·충전이 잠기고 손에 다트가 안 보인다. 실제로 확인했다: 투척선 뒤로 가면 `in_throw_zone=true`, 손·다트 표시, 한 발 던져 50점. HUD도 "다트 홀로 이동하세요" → "투척선 뒤 — 던질 수 있습니다"로 바뀐다.
- **② 방 1.5배**: 도면 비율은 그대로, `DART_HALL`·`LOUNGE`와 가구 위치만 1.5배. 가구 크기는 사람 기준이라 그대로다. 다트 홀 12 × 7.5m, 라운지 20.5 × 7.5m, 투척 거리 2.0 → **3.15m**(원래 설계 3.6m에 가까워졌다).
- **③ 레인만 막기**: 다트 홀 전체 폭을 가로막던 투명 벽을 없애고, 가운데 복도(x ±1.2)를 앞·양옆 세 면으로 막았다. 레인 바깥 양옆은 과녁 옆까지 걸어갈 수 있다. 로프도 같은 자리만 두른다.
  - 그래서 `in_throw_zone` 에 **"투척선 뒤"** 조건을 더했다 — 옆길로 돌아 과녁 옆에서 던지는 것을 막는다.
- 따라 고친 것: `test_game_look`(충돌 몸체 27 → 29), `test_prototype`(제한 구역 검사 → "옆은 지나가고 레인은 막힌다"), `run_first_idea.py`(자리·옆길·투척선 좌표), `render_first_idea.gd`·`render_game_look.gd`(라운지에서 던지던 장면을 투척선 뒤로, 카메라 위치를 넓어진 방에 맞춤).
