# 2026-11-23 · 로비 배경 펍을 경기 중에 놓아주기

## 왜

최적화 훑어보기에서 잰 값: 경기 중 전체 노드 6,220개 가운데 **2,817개가 타이틀 뒤 펍**이었다.
`lobby/lobby_backdrop.gd` 가 경기와 같은 방(`game/table/table.tscn`)을 따로 된 3D 세계(SubViewport)에 띄우는데,
경기에 들어가면 **그리기만 멈추고**(`UPDATE_DISABLED`) 노드·메시·조명·텍스처는 그대로 남아 있었다.

같은 훑어보기에서 이 게임은 GPU 가 아니라 **CPU·장면 복잡도**에 묶여 있다는 것도 확인했다
(1인칭에서 해상도를 65% 로 낮춰도 빨라지지 않았다). 그래서 안 보이는 펍 한 벌이 그대로 비용이었다.

## 무엇을

`lobby/lobby_backdrop.gd` 한 파일만 고쳤다.

- 타이틀이 `RELEASE_AFTER`(1.0초) 넘게 가려져 있으면 `_release()` 로 **SubViewport 를 통째로 `queue_free()`** 한다.
  방·소품·조명·캐릭터·날아가던 다트가 함께 빠진다.
- 타이틀로 돌아오면 `_process` 가 **붙잡아 둔 `PackedScene`(`_packed`)** 으로 다시 짓는다 — 펍 파일(2.2초)은 다시 읽지 않는다.
  검은 화면에서 다시 밝히는 것(`_fade_frames` → `FADE_IN`)은 처음 뜰 때와 같은 길을 탄다.
- 1초 여유를 둔 이유: 계정 화면처럼 잠깐 가려질 때 짓고 놓기를 반복하지 않게.
- 뷰포트 만들기를 `_make_viewport()` 로 빼고, 날아가는 다트의 착탄 알림에 `_table == null` 가드를 더했다
  (날아가는 중에 놓아주면 과녁이 없다).

## 잰 값 (1280×720 · RTX 4070 SUPER · 수직동기 끔 · 봇 경기)

| | 변경 전 | 변경 후 |
|---|---|---|
| 경기 중 전체 노드 | 6,220 | **3,403** |
| 경기 중 배경 노드 / 메시 / 조명 | 2,817 / 2,248 / 24 | **0 / 0 / 0** |
| 경기 중 프레임 시간 (1회차) | 8.39ms (119 FPS) | **7.57ms (132 FPS)** |
| 경기 중 프레임 시간 (2회차) | 8.22ms (122 FPS) | **6.94ms (144 FPS)** |

대가로 생긴 멈춤:

- **경기 시작**: 그대로다(약 160ms — 경기 장면을 짓느라 예전부터 있던 멈춤).
- **경기 시작 1초 뒤 놓아주는 프레임**: 셋째로 긴 프레임이 17ms → **27ms**. 한 프레임짜리 작은 끊김이다.
- **경기 → 로비 복귀**: 가장 긴 프레임 25ms → **150ms**. 다시 짓는 값이다.
  이 순간 화면은 어차피 검게 덮여 있다가 0.6초에 걸쳐 밝아지므로(`FADE_IN`) 전환 중에 묻힌다.

비디오 메모리는 경기 중 2,132MB → 2,013MB 로 약 120MB 만 줄었다.
텍스처 자체는 경기 펍과 **같은 파일을 공유**해서 배경을 놓아줘도 캐시에 남기 때문이다 — 이 변경의 이득은 메모리가 아니라 **노드 수**다.
