# 2026-10-27 봇이 투척선까지 걸어가 던진다

- 작업자 / 브랜치: Claude Code / `dev_1` (미커밋)
- 요청: "봇들이 앉아서 화살을 쏘는데 이거 고쳐줘. 지정된 라인까지 가서 던지게끔."

## 전까지의 동작

- `MatchController._accept_throw`가 `active.is_bot`이면 바로 반환 → 봇은 한 발도 던지지 않고 20초 뒤 0점이었다.
- `PlayerView.simulate`가 `identity.is_bot`이면 바로 반환 → 봇은 자리에 고정이었다.
- 그런데 `GameView._process`는 차례인 참가자가 봇이어도 `aiming`을 켰다 → **앉은 채로 오른팔만 드는** 모습이 20초 동안 이어졌다. 이게 "앉아서 쏜다"로 보인 부분이다.

## 지정된 라인

바닥에 선이 둘이다.

| 바닥 표시 | 좌표 | 뜻 |
| --- | --- | --- |
| 놋쇠 선 + "투 척 선" 글자 (`Oche`) | `TableView.THROW_LINE_Z` = -3.1 | 투척선 — **이번에 쓴 라인** |
| 놋쇠 띠 (`StandMarker`) | z = -0.6 | 예전 노란 선 자리. 의미 미정(`HANDOFF` 팀 확인 항목) — 쓰지 않았다 |

봇이 서는 자리는 레인 한가운데의 `BotDriver.throw_spot()` = `(0, 0, THROW_LINE_Z + 0.45)`다. 선을 넘지 않고, 사람의 이동 한계(z ≥ -2.85)와도 맞는다.

## 작업 내용

### 봇의 차례 행동 (`game/player/bot_driver.gd` 새 파일, `GameView._drive_bot`)

- 자기 차례(AIMING/FLIGHT/SETTLING)면 자리에서 일어나 투척선 뒤까지 걸어간다.
- 도착해 과녁을 보고 서면 `AIM_SECONDS`(1.2초)마다 `MatchController.bot_throw()`를 부른다. 비행 중에는 AIMING이 아니라 자동으로 한 발씩 끊긴다.
- 차례가 아니면 자기 자리로 걸어가 앉는다. **이미 앉아 있는 봇은 아예 건드리지 않는다**(기존 시험이 봇 위치를 직접 옮겨 쓰는 경우를 깨지 않으려고).
- 걸어가는 동안에는 `aiming`을 켜지 않는다 — 선에 서야 팔을 든다.
- `BotDriver`는 상태를 두지 않는다. 매 프레임 위치와 경기 상태만 보고 조작을 만든다.

### 테이블 비껴가기 (`BotDriver._steer`)

자리 `(0, 0, 5.5)`의 봇은 과녁으로 직진하면 원형 테이블에 정면으로 막혀 z=4.83에서 멈춘다(실제로 확인). 가는 길이 테이블 중심에서 `TABLE_RADIUS + TABLE_MARGIN`(1.05 + 0.8) 안으로 들어오면, 테이블 옆으로 그만큼 떨어진 지점을 보고 돌아간다. 경로를 기억하지 않고 매 프레임 다시 계산하므로 테이블을 지나면 바로 목표로 향한다. NavigationServer는 쓰지 않았다.

### 투척 경로 (`game/match/match_controller.gd`)

- `_accept_throw`의 뒷부분을 `_launch(peer_id, aim, charge, request_id)`로 분리했다. 사람과 봇이 같은 `solve_throw` → 비행 → `_land_dart` 채점 경로를 쓴다.
- `bot_throw(aim, charge)`는 방장에서만 돌고 네트워크 발신자가 없으므로 차례·봇 여부·발수·마감 시각·값 범위만 확인한다. 사람 요청의 발신자 검증(`_accept_throw`의 `is_bot` 거부 포함)은 그대로다.

### 봇도 움직일 수 있게 (`game/player/player.gd`)

`simulate`의 `if identity.is_bot: return`을 지웠다. 조작을 넣는 곳은 방장 한 곳뿐이고(`GameView`), 네트워크로 들어오는 조작은 `_accept_controls`가 여전히 봇 ID를 거부한다.

- 사람이 직접 마우스·키보드로 플레이한 느낌, 다른 PC·LAN·전용 서버 빌드는 확인하지 않았다.
